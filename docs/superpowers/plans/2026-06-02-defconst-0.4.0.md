> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a focused quality release: a hard compile error on duplicate constant *names*, plus Credo + Dialyzer static analysis wired into CI.

**Architecture:** Two independent, low-risk changes to an existing ~280-LOC pure-macro Elixir library. Feature 1 adds a duplicate-name check in the existing `Defconst.__before_compile__/1` hook (the only place with the full constant list). Feature 2 adds dev-only `credo`/`dialyxir` deps and a dedicated CI `quality` job. The existing ExUnit suite + a new compile-failure test are the gate.

**Tech Stack:** Elixir 1.19 / OTP 28.1.1, Mix, ExUnit, Credo, Dialyxir (Dialyzer), GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-06-02-defconst-0.4.0-design.md`

**Branch:** Create `defconst-0.4.0` off `master` **after** the 0.3.0 PR #5 is merged (so 0.4.0 builds on the released 0.3.0 baseline). All tasks commit to that branch.

## Task 1: Duplicate-name compile error (TDD)

**Files:**
- Modify: `lib/defconst.ex` (the `__before_compile__/1` macro)
- Test: `test/defconst_test.exs`

- [ ] **Step 1: Write the failing tests**

Append this `describe` block to `test/defconst_test.exs`, immediately before the final `end` that closes `defmodule DefconstTest`:

```elixir
  describe "duplicate constant names" do
    test "defconst with a duplicate name raises a clear compile error" do
      code = """
      defmodule DupViaDefconst do
        use Defconst

        defconst :a, 1
        defconst :a, 2
      end
      """

      err = assert_raise CompileError, fn -> Code.compile_string(code) end
      assert err.description =~ "duplicate constant name"
      assert err.description =~ ":a"
    end

    test "defenum with a duplicate name raises a clear compile error" do
      code = """
      defmodule DupViaDefenum do
        use Defconst

        defenum [
          {:a, 1},
          {:b, 2},
          {:a, 3}
        ]
      end
      """

      err = assert_raise CompileError, fn -> Code.compile_string(code) end
      assert err.description =~ "duplicate constant name"
      assert err.description =~ ":a"
    end

    test "unique names with duplicate values still compile and constant_of returns a list" do
      code = """
      defmodule UniqueNamesDupValues do
        use Defconst

        defconst :a, 1
        defconst :b, 1
      end
      """

      # Should NOT raise — duplicate values are a supported feature.
      [{mod, _bin} | _] = Code.compile_string(code)
      assert mod.constant_of(1) == [:a, :b]
    end
  end
```

- [ ] **Step 2: Run the tests to verify the first two FAIL**

Run: `mix test test/defconst_test.exs`
Expected: the two duplicate-name tests FAIL (currently a duplicate name compiles with only a soft warning, so no `CompileError` is raised — `assert_raise` fails). The "unique names / duplicate values" test PASSES already.

> If `Code.compile_string` leaves modules defined across tests and causes "module redefined" noise, that is benign for these assertions; the distinct module names (`DupViaDefconst`, `DupViaDefenum`, `UniqueNamesDupValues`) avoid collisions.

- [ ] **Step 3: Implement the duplicate-name guard**

In `lib/defconst.ex`, inside `defmacro __before_compile__(env)`, the function currently starts by building `constants`, `constant_map`, and `value_map`. Add the guard immediately after `constants` is computed and before `constant_map`. The current code is:

```elixir
    constants =
      env.module
      |> Module.get_attribute(:constants)
      |> Enum.reverse()

    constant_map = Enum.into(constants, %{})
```

Change it to:

```elixir
    constants =
      env.module
      |> Module.get_attribute(:constants)
      |> Enum.reverse()

    names = Keyword.keys(constants)
    duplicate_names = names -- Enum.uniq(names)

    unless duplicate_names == [] do
      raise CompileError,
        file: env.file,
        line: env.line,
        description:
          "Defconst: duplicate constant name(s): #{inspect(Enum.uniq(duplicate_names))}"
    end

    constant_map = Enum.into(constants, %{})
```

- [ ] **Step 4: Run the tests to verify all PASS**

Run: `mix test test/defconst_test.exs`
Expected: all duplicate-name tests pass (the two now raise `CompileError` with a message containing `duplicate constant name` and `:a`; the duplicate-value test still passes). No regressions in the rest of the file.

- [ ] **Step 5: Run the full suite + formatter**

Run: `mix test && mix format --check-formatted`
Expected: full suite green; formatter clean. If the formatter rewrites the new code, run `mix format` and re-check.

- [ ] **Step 6: Commit**

```bash
git add lib/defconst.ex test/defconst_test.exs
git commit -m "Raise CompileError on duplicate constant names (defconst/defenum)"
```

## Task 4: Add the CI quality job

**Files:**
- Modify: `.github/workflows/ci.yml`

- [ ] **Step 1: Append the `quality` job**

In `.github/workflows/ci.yml`, add a third job after the existing `format` job (sibling under `jobs:`). It needs dev deps (full `mix deps.get`), so it does NOT use `--only test`:

```yaml
  quality:
    runs-on: ubuntu-latest
    name: Quality (Credo + Dialyzer, Elixir 1.19 / OTP 28)
    steps:
      - uses: actions/checkout@v4
      - uses: erlef/setup-beam@v1
        with:
          elixir-version: "1.19"
          otp-version: "28"
      - name: Restore deps + PLT cache
        uses: actions/cache@v4
        with:
          path: |
            deps
            _build
          key: ${{ runner.os }}-quality-1.19-28-${{ hashFiles('**/mix.lock') }}
          restore-keys: ${{ runner.os }}-quality-1.19-28-
      - run: mix deps.get
      - run: mix credo --strict
      - run: mix dialyzer
```

- [ ] **Step 2: Validate the workflow**
