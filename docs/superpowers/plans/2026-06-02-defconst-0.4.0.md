- [ ] **Step 1: Write the failing tests**

Append this `describe` block to `test/defconst_test.exs`, immediately before the final `end` that closes `defmodule DefconstTest`:

```elixir
  describe "duplicate constant names" do
    test "defconst with a duplicate name raises a clear compile error" do
      code = """
      defmodule DupViaDefconst do
        use Defconst

        defconst :a, 1
        defconst :a, 2
      end
      """

      err = assert_raise CompileError, fn -> Code.compile_string(code) end
      assert err.description =~ "duplicate constant name"
      assert err.description =~ ":a"
    end

    test "defenum with a duplicate name raises a clear compile error" do
      code = """
      defmodule DupViaDefenum do
        use Defconst

        defenum [
          {:a, 1},
          {:b, 2},
          {:a, 3}
        ]
      end
      """

      err = assert_raise CompileError, fn -> Code.compile_string(code) end
      assert err.description =~ "duplicate constant name"
      assert err.description =~ ":a"
    end

    test "unique names with duplicate values still compile and constant_of returns a list" do
      code = """
      defmodule UniqueNamesDupValues do
        use Defconst

        defconst :a, 1
        defconst :b, 1
      end
      """

      # Should NOT raise — duplicate values are a supported feature.
      [{mod, _bin} | _] = Code.compile_string(code)
      assert mod.constant_of(1) == [:a, :b]
    end
  end
```

- [ ] **Step 2: Run the tests to verify the first two FAIL**

Run: `mix test test/defconst_test.exs`
Expected: the two duplicate-name tests FAIL (currently a duplicate name compiles with only a soft warning, so no `CompileError` is raised — `assert_raise` fails). The "unique names / duplicate values" test PASSES already.

> If `Code.compile_string` leaves modules defined across tests and causes "module redefined" noise, that is benign for these assertions; the distinct module names (`DupViaDefconst`, `DupViaDefenum`, `UniqueNamesDupValues`) avoid collisions.

- [ ] **Step 3: Implement the duplicate-name guard (expansion-time + before_compile backstop)**

Detect duplicates at `defconst` **expansion time** so the error is raised _before_ the
duplicate `defmacro`/`@doc` clause is emitted — otherwise the old soft warnings
("this clause for `x/0` cannot match", "redefining @doc") still print before the hard error.

In `lib/defconst.ex`, in the `defmacro defconst(name, value)` body, call a name-registering
guard before building the quote:

```elixir
  defmacro defconst(name, value) do
    caller_module = __CALLER__.module
    register_name!(caller_module, name, __CALLER__)
    var = Macro.var(name, __MODULE__)

    quote do
      Module.put_attribute(unquote(caller_module), :constants, {unquote(name), unquote(value)})
      # ... unchanged @doc + defmacro ...
    end
  end
```

Add the helper. It manages a plain `:defconst_names` list **manually** at expansion time — do
NOT rely on a `use`-time `register_attribute(accumulate: true)`, because that has not executed
when the first `defconst` expands (it would store a scalar and the second read crashes):

```elixir
  defp register_name!(module, name, caller) do
    seen = Module.get_attribute(module, :defconst_names) || []

    if name in seen do
      raise CompileError,
        file: caller.file,
        line: caller.line,
        description: "Defconst: duplicate constant name: #{inspect(name)}"
    end

    Module.put_attribute(module, :defconst_names, [name | seen])
  end
```

Keep a backstop in `__before_compile__/1` (defense in depth) using the full `constants` list:

```elixir
  defp ensure_unique_names!(constants, env) do
    names = Keyword.keys(constants)
    duplicate_names = names -- Enum.uniq(names)

    unless duplicate_names == [] do
      raise CompileError,
        file: env.file,
        line: env.line,
        description:
          "Defconst: duplicate constant name(s): #{inspect(Enum.uniq(duplicate_names))}"
    end
  end
```

(call `ensure_unique_names!(constants, env)` near the top of `__before_compile__/1`).

Run: `mix test test/defconst_test.exs`
Expected: all duplicate-name tests pass; the two duplicate cases raise `CompileError` (message contains `duplicate constant name` and `:a`) with **no** "clause cannot match"/"redefining @doc" warnings printed; the duplicate-value test still passes. No regressions.
