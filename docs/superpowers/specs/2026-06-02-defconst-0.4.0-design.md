# Defconst 0.4.0 — Design Spec

**Date:** 2026-06-02
**Status:** Approved
**Goal:** A focused quality release: catch duplicate constant **names** at compile time, and
add static analysis (Credo + Dialyzer) to CI.

## Background

0.3.0 modernized the library (toolchain, deps, CI, release automation). 0.4.0 builds on that
with two high-value, low-risk improvements drawn from a review of larger proposals. Explicitly
**out of scope** (considered and declined): literal-pool/AST "optimization" (the
macro-expands-to-literal design is already zero-overhead and pool-friendly), `import`-instead-of-`use`
(`use` is required for the `@before_compile` hook), `to_string/1`/`to_atom/1` sugar (redundant
with existing `EnumType.zero` / `value_of` / `constant_of`), and Ecto.Type support (separate
scope/dependency decision, possible future release).

## Decisions

| Decision | Choice |
|---|---|
| Release version | `0.4.0` |
| Feature 1 | Duplicate constant **name** → hard `CompileError` (duplicate **values** stay supported) |
| Feature 2 | Credo + Dialyzer as **dev-only** deps (`credo` and `dialyxir` both `only: :dev`), dedicated CI `quality` job |
| Feature 3 | Housekeeping: fix `mix docs` "LICENSE does not exist" warning; bump all GitHub Actions to their latest major tags |
| Delivery | New branch off **verified `origin/master`** (released 0.3.0) after PR #5 merges. The `v0.3.0` tag is left as-is (off-mainline docs-only commit, accepted as harmless); the hard release-safety tag check is applied to **`v0.4.0` at release time**, not `v0.3.0` |
| Existing CI | Test matrix + format job unchanged; add a separate `quality` job; bump action versions in both workflows |

## Feature 1 — Duplicate-key compile error

**Where (primary):** at `defconst` **expansion time**. Each `defconst` records its (literal
atom) name in a plain `:defconst_names` list attribute managed entirely at expansion time, and
raises `CompileError` immediately if the name was already seen. Doing it here — *before* the
duplicate `defmacro`/`@doc` clause is emitted — means the old soft warnings
("this clause for `x/0` cannot match", "redefining @doc") are never produced; the user sees only
the clean hard error. This covers repeated `defconst`, `defenum` lists, and any mix (defenum
expands to ordered `defconst` calls). Note: the name list is managed manually rather than via a
`use`-time `register_attribute(accumulate: true)`, because that registration has not executed
yet when the first `defconst` expands.

**Where (backstop):** `Defconst.__before_compile__/1` also checks `Keyword.keys(constants)` for
duplicates and raises, as defense in depth.

**Behavior:** message e.g. `** (CompileError) Defconst: duplicate constant name: :a`.

**Not changed:** duplicate *values* remain valid — `constant_of/1` returns a list when several
names share a value (existing, tested behavior). This feature only rejects duplicate *names*.

**Today's behavior being replaced:** a duplicate name currently emits only a soft
"this clause for `x/0` cannot match" warning and silently keeps both; 0.4.0 makes it a clear
hard error **with no warning noise**.

**Tests:** a duplicate name (via `defconst` and via `defenum`) fails compilation with the
message; existing unique-name and duplicate-value cases still pass.

## Feature 2 — Credo + Dialyzer

**Deps (`mix.exs`):** both **`only: :dev`** — so the test matrix's `mix deps.get --only test`
never pulls them, preserving the consumer-floor proof and the "test jobs fetch no tooling"
contract.
- `{:credo, "~> 1.7", only: :dev, runtime: false}`
- `{:dialyxir, "~> 1.4", only: :dev, runtime: false}`

**Config:**
- `.credo.exs` (generated default, `--strict`-clean).
- Dialyzer config in `mix.exs` `project/0`: a stable PLT path under `_build` for CI caching.

**CI — new `quality` job** in `ci.yml` (Elixir 1.19 / OTP 28):
- Full `mix deps.get` (these are dev deps, so NOT `--only test`).
- Cache the Dialyzer PLT keyed by OS + Elixir/OTP + `mix.lock`.
- `mix credo --strict`
- `mix dialyzer`

The existing test matrix (`--only test`) and format job are unchanged. Any Credo/Dialyzer
findings on the current code are fixed as part of this work.

## Feature 3 — Housekeeping

**LICENSE doc warning.** `mix docs` (and `mix hex.publish`) warns
`documentation references file "LICENSE" but it does not exist` because the README links to
`LICENSE` (in the license badge and the License section) but `LICENSE` isn't a doc extra. Fix
by adding `"LICENSE"` to the `docs: [extras: ...]` list in `mix.exs`. Verified: this clears
the warning (0 remaining) and renders the license in HexDocs; the README's relative links stay.

**GitHub Actions to latest major tags.** Pin to floating **major** tags (the convention for
Actions — auto-receives patches, not exact SHA/patch immutability). Bump in **both** `ci.yml`
and `release.yml`:
- `actions/checkout@v4` → `@v6` (latest major; v6.x)
- `actions/cache@v4` → `@v5` (latest major; v5.x; `ci.yml` only)
- `erlef/setup-beam@v1` — already the latest major (v1.x); leave at `@v1`.

(Floating major tags auto-receive patch updates, so exact patch numbers are intentionally not
pinned here and not tracked in this doc.)

## Release bookkeeping
- Bump `@version` to `0.4.0`.
- CHANGELOG `[0.4.0]` entry (Added: duplicate-name compile check, Credo + Dialyzer CI; Fixed: LICENSE doc warning; Changed: Actions bumped).

## Out of scope
- `to_string/1` / `to_atom/1`, Ecto.Type, any macro/guard "optimization", `import` API change.
- Changing the existing test matrix structure or the release workflow's trigger/logic (only action versions change).

## Success criteria
- Defining the same constant name twice (via `defconst` or `defenum`) fails compilation with a
  clear message; unique names and duplicate values are unaffected; full suite green.
- `mix credo --strict` and `mix dialyzer` pass locally and in the new CI `quality` job; the
  test matrix still fetches no tooling (`credo`/`dialyxir` are `only: :dev`).
- `mix docs` emits no "LICENSE does not exist" warning.
- All GitHub Actions pinned to their latest major in both workflows.
- Version `0.4.0` with CHANGELOG + README (incl. dependency snippet) updated; existing CI jobs still green.
